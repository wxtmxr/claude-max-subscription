## 用量限制的真实算法：别只盯着「多少条消息」

官方对 Max 用量的定义是「Pro 每 5 小时会话额度的 5 倍或 20 倍」，同时还有一套跨模型的每周限额，每周在固定时间重置，和你订阅开始的时间无关。

「45 条」「900 条」这些数字是长期使用总结出来的估算值，前提是短对话、不带附件。实际机制按 token 算，同一档订阅，不同人的体感差距可以非常大。几个变量：

**模型选择。** Opus 比 Sonnet 耗额度得多。如果把 Opus 设为默认模型，等于拿着更小的预算干活。日常草稿用 Sonnet，把 Opus 留给真正需要深度推理的任务，是更省的用法。

**扩展思考（Extended Thinking）。** 开一次复杂推理的 token 消耗最高能到普通回复的 5 倍。把它当默认模式用，是很多人「莫名其妙就撞限额」的最常见原因。

**coding agent 和聊天共享额度。** 这是最容易踩的误区：终端里跑一上午 coding agent，下午再想分析文档，掏的是同一个池子，不是两个独立账户。

**高峰期消耗更快。** 工作日太平洋时间早 5 点到 11 点（美东 8 点到下午 2 点），有社区统计称消耗速度约为平时的 1.3–1.5 倍，官方没有公布确切数字。如果你的重度和美国上班时间重叠，实际可用量会比标称的少。

**对话越长烧得越快。** 每条新消息都要背着前面的全部上下文。coding agent 里用 /compact 及时压缩，或者干脆开新会话，是不花一分钱的省钱手段。

还有一条对 Max 用户尤其重要：单月会话数超过 50 个，官方可能对你的访问做限制。这不是硬性封顶，而是逐案判断的弹性基准——换句话说，Max 设计给的是高强度的人类使用，不是让你 24 小时跑无人值守的自动化流水线。那种需求应该走 API。

**留在 Pro**，如果你：每周用几次到每天轻度使用；主要写作、研究、查资料、偶尔写代码；日均消息 50 条以内；几乎没等过额度重置。低强度区间里，Pro 的性价比没有对手。

## 几个高频问题

**撞到限额怎么办？** 等 5 小时窗口重置，有些情况下可以降速继续用。周限额在固定时间自动刷新。另外账户里有限额重置（limit reset）功能，可以把 5 小时额度或周额度直接拉满。

**Max 5x 和 Max 20x 功能有区别吗？** 没有。两档功能完全一致，差别只有额度。选哪个，纯粹取决于你需要多少用量。

**Max 能年付吗？** 不能，目前只有月付。这也是为什么中途降档不退差价、只顺延到下个周期。

**不想续了怎么取消？** 网页端在 Settings → Billing 里管理或取消；iOS 订阅走 iPhone 设置里的 Apple ID 订阅管理。换支付渠道时，先取消旧渠道，等周期结束再在新渠道开通，避免重复扣费。
